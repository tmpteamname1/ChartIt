# 5. Ispitivanje

## 5.1 Pristup ispitivanju

**Pristup ispitivanju:** Poslužiteljski dio ispituje se automatiziranim testovima u Djangu (`TestCase`, za API `APITestCase` iz DRF-a), smještenima u `backend/<aplikacija>/tests.py`. Testovi provjeravaju pravila modela i ograničenja u bazi (npr. OIB, cijena, kapacitet, koordinate luke), ponašanje API-ja (filtri, straničenje, format greške, CSRF zaštita) te ovlasti prema ulogama i izolaciju tvrtki. Za izolaciju se uvijek koriste dvije tvrtke i zahtjev za objekt druge tvrtke. Testovi se izvode nad PostgreSQL-om, kao u produkciji, jer ograničenja rezervacija ovise o proširenju `btree_gist` (ADR-03).

Svi testovi, lint, provjera formatiranja, build klijenta s provjerom tipova (`tsc -b`) i provjera nedostajućih migracija izvode se u CI-ju (GitHub Actions) na svakom pull requestu i pushu u `main`. Pull request se ne može spojiti dok provjere ne prođu ([poglavlje 6](6-Postavljanje-instalacija-i-konfiguracija.md#kontinuirana-integracija-ci)).

Klijentska aplikacija zasad nema automatiziranih testova; ponašanje u pregledniku provjerava se ručno prema sustavskim ispitnim slučajevima (ST) u lokalnom razvoju i na javnoj instanci, a autor promjene i pregledavatelj provjeravaju ekran u pregledniku prije spajanja. Alati za automatizaciju preglednika (npr. Selenium) zasad se ne koriste. Nefunkcijski zahtjevi provjeravaju se gdje je to već moguće: HTTPS i dostupnost javne instance (NF-04, NF-07), ovlasti i izolacija tvrtki (NF-02).
